1. PROJECT OVERVIEW & PHILOSOPHY
--------------------------------------------------------------------------------
Project Name      : कर्म प्रधान (Karma-Driven Productivity Dashboard)
Core Motto        : "कर्म प्रधान विश्व रचि राखा, जो जस करहि सो तस फल चाखा"
                    ("The world is built on the primacy of karma — as you sow, 
                     so shall you reap")
Purpose           : An all-in-one, dark-themed productivity dashboard designed
                    for students, developers, and professionals to manage daily
                    tasks, evaluate weekly/monthly performance, enforce recovery 
                    and flexibility rules, and align daily actions with long-term 
                    aspirations.
Execution Model   : Single-instance local Streamlit web application backed by 
                    SQLite database storage with zero required cloud services.

3. TECHNOLOGY STACK & DEPENDENCIES
--------------------------------------------------------------------------------
- Language          : Python 3.8+
- UI Framework      : Streamlit (>= 1.32.0)
  * Multi-tab layout (`st.tabs`), reactive forms, column configurations, sliders,
    metric badges, and CSV export.
- Data Visualization: Plotly (>= 5.20.0)
  * `plotly.graph_objects` (Bar, Pie/Donut, Gauge, Scatter, Scatterpolar/Radar)
  * `plotly.subplots.make_subplots` (Dual-axis charts)
- Data Processing   : Pandas (>= 2.1.0)
  * Dataframe aggregation, grouping, calendar gap filling, date manipulation
- Database Engine   : SQLite3 (`sqlite3` built-in Python module)
  * Zero-config, single-file ACID transactional persistence
- Fonts & Typography: Google Fonts via CSS injection:
  * 'Inter' (Primary UI)
  * 'Noto Sans Devanagari' (Sanskrit quotes & Hindi headings)


4. DATABASE ARCHITECTURE & SCHEMA SPECIFICATION
--------------------------------------------------------------------------------
Database File: karma_dashboard.db

TABLE: tasks
  - id           : INTEGER PRIMARY KEY AUTOINCREMENT
  - date         : TEXT NOT NULL (YYYY-MM-DD)
  - name         : TEXT NOT NULL (Task description / title)
  - priority     : TEXT NOT NULL ('high', 'medium', 'low')
  - est_mins     : REAL DEFAULT 0 (Estimated completion time in minutes)
  - actual_mins  : REAL DEFAULT 0 (Actual recorded time in minutes)
  - pct_done     : REAL DEFAULT 0 (Progress completion percentage 0-100)
  - completed    : INTEGER DEFAULT 0 (Boolean flag: 1 = completed, 0 = pending)
  - category     : TEXT DEFAULT 'work' ('work', 'study', 'health', 'personal', 'creative', 'balance')
  - created_at   : TEXT DEFAULT CURRENT_TIMESTAMP

TABLE: daily_log
  - id           : INTEGER PRIMARY KEY AUTOINCREMENT
  - date         : TEXT UNIQUE NOT NULL (YYYY-MM-DD)
  - total_tasks  : INTEGER DEFAULT 0
  - done_tasks   : INTEGER DEFAULT 0
  - avg_pct      : REAL DEFAULT 0
  - mood         : TEXT DEFAULT 'neutral'
  - notes        : TEXT DEFAULT ''

TABLE: long_term_goals
  - id           : INTEGER PRIMARY KEY AUTOINCREMENT
  - title        : TEXT NOT NULL
  - deadline     : TEXT (YYYY-MM-DD)
  - progress     : REAL DEFAULT 0 (Percentage 0-100)
  - category     : TEXT DEFAULT 'career' ('career', 'project', 'health', 'learning', 'personal', 'other')
  - description  : TEXT DEFAULT ''
  - created_at   : TEXT DEFAULT CURRENT_TIMESTAMP

TABLE: flex_log
  - id           : INTEGER PRIMARY KEY AUTOINCREMENT
  - date         : TEXT NOT NULL (YYYY-MM-DD)
  - what_failed  : TEXT (Task or routine that could not be completed)
  - why_failed   : TEXT (Underlying root cause or interruption)
  - reallocation : TEXT (Strategy to shift, reallocate, or recover)
  - created_at   : TEXT DEFAULT CURRENT_TIMESTAMP

TABLE: mission_profile [Phase 2 — Active]
  - id                      : INTEGER PRIMARY KEY CHECK (id = 1) (Singleton profile)
  - life_mission            : TEXT (Primary overarching life mission)
  - career_aspirations      : TEXT (Core professional career vision)
  - learning_goals          : TEXT (Technical mastery & engineering targets)
  - personal_growth         : TEXT (Philosophy of discipline & consistency)
  - identity_statement      : TEXT ("The person I want to become")
  - why_it_matters          : TEXT (Deep personal reason for the mission)
  - what_it_enables         : TEXT (Autonomy, freedom, family security, impact)
  - target_outcome          : TEXT (Specific measurable target outcome)
  - target_date             : TEXT (YYYY-MM-DD target date)
  - motivational_statements : TEXT (JSON array of personal affirmations)
  - show_sanskrit_motto     : INTEGER DEFAULT 1 (Toggle Sanskrit quote card)
  - quote_rotation_mode     : TEXT DEFAULT 'daily' ('daily' | 'all')
  - updated_at              : TEXT DEFAULT CURRENT_TIMESTAMP

TABLE: daily_intentions [Phase 2 — Active]
  - id                   : INTEGER PRIMARY KEY AUTOINCREMENT
  - date                 : TEXT UNIQUE NOT NULL (YYYY-MM-DD)
  - intention            : TEXT NOT NULL (Daily focus & North Star)
  - top_priority_task_id : INTEGER (Anchor link to today's #1 task)
  - why_today_matters    : TEXT (Daily reflection on long-term alignment)
  - energy_level         : INTEGER DEFAULT 3 (1-5 energy/focus scale)
  - created_at           : TEXT DEFAULT CURRENT_TIMESTAMP

TABLE: goal_milestones [Phase 3 — Active]
  - id          : INTEGER PRIMARY KEY AUTOINCREMENT
  - goal_id     : INTEGER NOT NULL (Foreign key to long_term_goals.id)
  - title       : TEXT NOT NULL (Milestone title/deliverable)
  - target_date : TEXT (YYYY-MM-DD target deadline)
  - completed   : INTEGER DEFAULT 0 (0: Pending, 1: Completed)
  - weight      : REAL DEFAULT 1.0 (Contribution weight towards goal progress)
  - notes       : TEXT (Context, deliverables, or checklist notes)
  - created_at  : TEXT DEFAULT CURRENT_TIMESTAMP

EXTENSIONS [Phase 3 — Backward Compatible]:
  - `long_term_goals` columns added: motivation, start_date, desired_outcome, success_criteria, status, blockers, next_action, review_frequency
  - `tasks` columns added: goal_id (FK to long_term_goals), milestone_id (FK to goal_milestones), blockers


Data Seeding Mechanism:
  - Function `seed_demo_data()` checks if `tasks` is empty.
  - If empty, creates 14 days of realistic task history with randomized
    completion rates, time variances, and 4 starter long-term goals.
  - Function `get_mission_profile()` initializes default aspirational engineering profile
    if `mission_profile` table is empty.

6. APPLICATION ARCHITECTURE & CODE MODULES (app.py)
--------------------------------------------------------------------------------
The application is organized into the following logical sections in `app.py`:

[Section 1] Configuration & Page Initialization (Lines 18 - 234)
  - Page config: `layout="wide"`, expanded sidebar, favicon, title
  - CSS injection: Typography, theme colors, cards, progress bars, tab stylings

[Section 2] Data Layer & SQLite Helpers (Lines 235 - 472)
  - `get_conn()`: Returns thread-safe SQLite connection
  - `init_db()`: Initializes the 4 schema tables
  - CRUD Task Operations:
    * `get_tasks(for_date)`
    * `add_task(name, priority, est_mins, category, for_date)`
    * `update_task(task_id, actual_mins, pct_done, completed)`
    * `delete_task(task_id)`
  - Aggregation Queries:
    * `get_weekly_data()`: Rolling 7-day window totals, completions, and average %
    * `get_monthly_data()`: Current calendar month day-by-day stats
    * `get_month_record(year, month)`: Complete month grid with priority splits
  - Goal Management:
    * `get_goals()`, `add_goal(...)`, `update_goal_progress(...)`, `delete_goal(...)`
  - Flexibility Log:
    * `log_flex(...)`, `get_flex_logs()`
  - Demo Seeder:
    * `seed_demo_data()`: Initializes sample historical data if DB is empty

[Section 3] Plotly Theme Engine (Lines 473 - 497)
  - `CHART_THEME`: Transparent background, Inter typography, custom legend
  - `AXIS_STYLE`: Coordinated grid lines and borders (#1a3358)
  - `apply_theme(fig, height, **kwargs)`: Unified chart layout applicator

[Section 4] Sidebar Navigation & Quick Actions (Lines 498 - 549)
  - Brand header with Devanagari typography

  - "Add New Task" Form: Task Name, Estimated Hours/Minutes, Priority, Category
  - "Balance Slot" Section: Quick logger for family, entertainment, and rest

[Section 5] Global Hero Banner & Quick KPI Strip (Lines 550 - 609)

7. DATA FLOW & USER INTERACTION CYCLE
--------------------------------------------------------------------------------
1. Initiation:
   User selects date in Sidebar -> Database queried for specified date (`get_tasks`).
2. Task Creation:
   User submits task -> `add_task()` inserts into SQLite -> Streamlit executes `st.rerun()`.
3. Execution & Tracking:
   User adjusts time spent / progress sliders -> `update_task()` updates database.
4. Review & Reflection:
   - Weekly tab computes rolling efficiency & streak continuity.
   - Monthly & 1-Month Record tabs aggregate volume, bottlenecks, and completion rate.
   - Failures recorded in Flexibility Log to prevent burnout and encourage recovery.
5. Strategic Alignment:
   - Goals tracked via radar chart and tied back to daily execution habits.
